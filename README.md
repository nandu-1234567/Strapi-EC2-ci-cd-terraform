Automate Strapi Deployment with GitHub Actions and Terraform

This project automates the deployment of a Strapi application using Docker, Terraform, and GitHub Actions. The pipeline builds and pushes Docker images automatically, and deploys them on an EC2 instance via Terraform.

Project Overview

CI Pipeline: Automatically builds and pushes a Docker image when code is pushed to the main branch.

CD Pipeline: Deploys the updated Docker image to an EC2 instance using Terraform.

Deployment Verification: Strapi can be accessed via the public IP of the EC2 instance.

Task Breakdown
1. CI/CD - Code Pipeline

The CI workflow runs whenever there is a push to the main branch. It performs the following actions:

Builds the Docker image of Strapi.

Pushes the Docker image to Docker Hub or AWS ECR.

Saves the image tag as an output for the Terraform CD workflow.

2. CD - Terraform Pipeline

The CD workflow is triggered manually and handles deployment. It performs the following actions:

Checks out the repository code.

Configures AWS credentials from GitHub Secrets.

Runs Terraform to provision the EC2 instance and deploy the Docker container.

Uses the Docker image tag output from the CI workflow to pull and deploy the Strapi container on EC2.

EC2 Deployment Configuration

The EC2 instance is provisioned using Terraform.

SSH access is enabled using a private key generated by Terraform.

Security group allows inbound connections on port 22 (SSH) and port 1337 (Strapi).

Docker is installed automatically, and the Strapi container is deployed dynamically using the Docker image from CI.

Deployment Verification

After deployment:

Retrieve the public IP from Terraform outputs.

Access Strapi in your browser using the public IP and port 1337.

SSH into the EC2 instance using the generated private key if needed.

GitHub Secrets Required

Docker Hub username

Docker Hub password or personal access token

AWS access key ID

AWS secret access key
